Inkception — Lock Down the URL

Cloudflare Access the easy way · email one-time PIN (no Google OAuth needed) · ~15 minutes
Why this works: we deploy the site to Cloudflare Pages (free, gives us our own URL that Cloudflare controls), then put a Zero Trust Access wall in front of it. Only the 4 allowlisted emails get in. No code changes needed — the app is already ready.

Before you start (2 min)

✓
Create a free Cloudflare account at cloudflare.com (if you don't have one) and log in. Keep the GitHub repo public (it already is).

Step 1 — Deploy the site to Cloudflare Pages

1
Log in at cloudflare.com. In the left sidebar click Workers & Pages.
2
Click Create → Pages → Connect to Git.
3
Authorize GitHub if asked, then pick the repo successpartner10/Inkception.
4
Build settings: Framework preset = Vite · Build command = npm run build · Build output directory = dist.
5
Click Save and Deploy. Wait ~1 minute. Cloudflare shows you a URL like https://inkception.pages.dev — write it down. ✓ Done

Step 2 — Turn on Zero Trust (free)

6
Go to cloudflare.com account home. Click the Zero Trust product tile (or visit one.one.one.one → Zero Trust / cloudflare.com/products/zero-trust/ → Try Zero Trust free).
7
Pick a team name (anything, e.g. inkception), choose the Free plan, finish the wizard.
If you can't find Zero Trust later: dash.cloudflare.com → select your account → left sidebar has Zero Trust.

Step 3 — Create the Access application

8
Inside Zero Trust, left sidebar: Access → Applications → Add an application → Self-hosted.
9
Application name: Inkception · Domain: enter your inkception.pages.dev (subdomain + domain fields). Leave the rest default, click Next.
10
Login methods: turn ON only One-time PIN. Turn OFF Google/GitHub/etc. if shown. Click Next.
This is the "no Google OAuth" trick — Cloudflare emails a login code, so we skip Google Cloud Console entirely.

Step 4 — The allowlist policy (THE critical step)

11
On the policy page click Add a policy. Policy name: Allowlist · Action: Allow.
12
Under Configure rules: Include → Emails → add each address, then click Apply:

13
Click Save policy → then Save application.
Don't skip the policy. The One-time PIN login alone lets anyone with an email sign in — the Include → Emails rule is what locks it to your 4 addresses.

Step 5 — Test it

14
Open https://inkception.pages.dev in a private/incognito window → you'll be asked for your email → enter one of the 4 → Cloudflare emails you a code → enter it → the app loads. ✓
15
Try a different email (e.g. a second Gmail you have) → you should get a blocked page. ✓ Locked down

If something looks different

  • No "Workers & Pages"? It's in the account's left sidebar after you log in at dash.cloudflare.com.
  • No "Zero Trust" in the sidebar? You may still be on the old plan page — click the Zero Trust product tile on the Cloudflare home dashboard first, then follow the wizard once.
  • Pages URL has your repo name in it? Fine — any *.pages.dev URL works; use whatever it gives you.
  • Worried about the old GitHub Pages URL? You can leave it up; the new locked URL is the one you share. (To fully kill the old one, delete the repo or remove Pages in repo Settings → Pages → Unpublish.)
Keep this safe: only these 4 emails can log in. To change who's allowed later, edit the policy in Zero Trust → Access → Applications → Inkception → Policies.
